## Source contract

The source row grain is an invoice line. `InvoiceNo` is not unique; the
candidate line key is invoice number plus line ordinal in source order. The
controlled fixture makes that ordinal explicit as `line_id`. `StockCode` is the
product business key and `CustomerID` is a source-scoped customer business key.
Neither is an enterprise identity: all durable keys include `source_system`.

`InvoiceDate` is event time. `event_seq` is fixture ingestion order and is used
only to make replay/correction precedence deterministic. Currency is unspecified
by the source, so the assessment compares decimal line amounts but does not
label or convert a currency.

| Source field | Meaning | Controlled representation |
|---|---|---|
| InvoiceNo | Invoice identifier; leading `C` denotes cancellation | `invoice_no`, plus explicit `event_type` |
| StockCode | Product/item code | `stock_code` |
| Description | Product description | `description` |
| Quantity | Units on the line | signed `quantity` |
| InvoiceDate | Invoice event timestamp | `invoice_ts` |
| UnitPrice | Price per unit | `decimal(18,2)` |
| CustomerID | Source customer identifier; may be missing | `customer_id` |
| Country | Customer/order country | `country` |

Known source anomalies relevant to this assessment are missing customer IDs,
cancellation invoices, repeated invoice numbers, non-positive quantities or
prices, and mutable descriptions. Null customer IDs map to `UNKNOWN`; an
unresolved non-null customer maps to `SKELETON`; deliberately absent product
codes remain visible for DQ rather than silently creating a product.

## Ordered mutation ledger

Rows 1-3 are the baseline transcription. Rows 4-14 are synthetic and exist only
to exercise the agreed contract.

| State / max sequence | Mutation | Expected consequence |
|---|---|---|
| baseline / 3 | Three source lines | 3 facts, 3 products, 2 customers |
| dimension_changes / 5 | Customer country change; product description correction | Customer SCD2 version; product SCD1 overwrite |
| incremental / 6 | New sale | One new fact resolved to the current customer |
| replay / 7 | Exact replay of line `uci-536368-1` | Merge remains one fact |
| late_dimension / 8 | Customer change earlier than the baseline | Rebuilt SCD2 timeline remains non-overlapping |
| late_fact / 9 | Fact inside the late customer interval | Temporal join resolves it |
| unknowns / 10 | Sale with null customer | `UNKNOWN` resolution |
| duplicates / 11 | Same customer/time correction | Later `event_seq` wins; no zero-length duplicate version |
| orphans / 12 | Missing product and non-null customer with no dimension attributes | Product is absent; customer resolution is `SKELETON` |
| identity / 13 | Same customer text from ERP | Source-scoped key prevents collision; crosswalk links identities |
| cancellation / 14 | Signed cancellation line | Retained as a cancellation fact with negative amount |

Out of scope for this small source contract are physical deletes, exchange-rate
conversion, personally identifying attributes, and claims that source customer
IDs identify real people across systems.
