# Phase 2.7 controlled capability assessment

Status: complete  
Decision scope: the controlled retail contract only; no migration or parity claim

## Evidence-backed findings

| Capability | Native dbt reference | Framework/PySpark reference | Classification |
|---|---|---|---|
| DAG and dependency declaration | `source`/`ref`, manifest lineage | Explicit orchestration/config | dbt stronger for authored SQL lineage |
| Incremental facts and SCD1 | Native Delta merge materialization | Explicit DataFrame overwrite in assessment implementation | dbt stronger in this fixture |
| SCD2 target | SQL window model plus native snapshot evidence | Explicit PySpark window model | Equivalent target rows; framework offers more direct algorithm control |
| Replay | Merge `unique_key` plus deterministic source rank | Deterministic source rank | Equivalent |
| Late facts/dimensions | Full scoped source re-evaluation | Full scoped source re-evaluation | Equivalent for bounded fixture; neither proves production watermark policy |
| Unknown/skeleton handling | Explicit SQL classifications | Explicit DataFrame classifications | Equivalent |
| Identity collision | Source-scoped keys and crosswalk model | Same target contract | Equivalent |
| DQ | Generic and singular dbt tests | Reconciliation invariants | dbt stronger developer feedback; framework can enforce runtime policies |
| Docs/artifacts | Native manifest, run results, compiled SQL and docs graph | YAML/config plus application logs | dbt stronger |
| Differential proof | Consumed by independent reconciler | Consumed by independent reconciler | Equivalent outputs in every local state |
| Recovery/operations | Not exercised by this dbt fixture | Framework Phase 1.8d operator recovery proof | Framework stronger, but outside model equivalence boundary |
| Photon/Unity Catalog/Serverless | Native dbt task passed on the Free Edition warehouse | Dependent Serverless PySpark task passed | Equivalent correctness for included targets |
| CDF | Not exercised | Not exercised | Not comparable |

The local result is deliberately narrow: dbt-spark 1.11.0 and dbt Core 1.11.7
successfully drive Spark 4.0.1/Delta 4.2.0 through pinned Thrift. All 11 ordered
states have equal rows, types and aggregates, with zero unexplained differences,
duplicate fact keys, customer temporal overlaps, or current-member violations.

## Prioritized gap backlog

1. Add framework-native manifest/lineage output that exposes inputs, compiled
   execution plan, target relations and tests in one machine-readable artifact.
2. Add declarative uniqueness, accepted-values and temporal-overlap checks with
   dbt-like local feedback before execution.
3. Define production late-arrival and bounded-reprocessing policy; this fixture
   intentionally recomputes the scoped history.
4. Compare merge planning and file behavior at representative scale rather than
   infer performance from 14 fixture events.
5. Preserve per-state framework execution metrics beside dbt `run_results`.
6. Decide whether native snapshots are a supported framework concept or remain
   an intentionally dbt-only convenience.
7. Add a separately scoped CDF comparison if CDF becomes part of the framework
   contract; Phase 2 correctly classifies it as not comparable.

## Decision

Retain the framework where recovery control, explicit PySpark algorithms, and
operational integration are the primary value. Treat dbt as a strong reference
for SQL developer workflow, lineage, testing, documentation, and incremental
materializations. Do not begin a migration or claim compatibility from this
assessment. The Free Edition conformance run did not change this boundary.
